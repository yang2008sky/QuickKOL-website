# QuickKOL Blog

把竞品关键词转成能满足搜索需求、具有证据与独立价值、自然连接达人发现任务的内容。QuickKOL 是 **AI 找达人工具**；以当次核验的产品能力为准，不把它写成代理机构、买粉服务或具备所有营销功能的平台。

## 输入与工作范围

- 接受关键词列表、竞品页面或关键词导出、单篇主题、待优化文章。关键词名单无需用户先手工填写策划表。
- 批量输入保留原词、竞品 URL、数据工具、国家、语言、日期及已有指标；缺失字段标为未知。工具估算不写成真实访问或转化。
- 确定目标读者、市场、语言与交付范围。已有上下文能确定时直接继续；缺少 repo 不妨碍研究与稿件交付。
- 默认交付中英文，内容深度和事实一致；用户另有语言要求时按要求执行，不自动扩展全站所有语言。
- 区分策划、研究、草稿、资源制作、接入网站、远端推送、上线。完成用户已授权的阶段，不把写作请求解释为自动发布。
- 区分内容修改与展示修改。用户只调整字体、颜色、间距、背景或目录时，保留原文、标题、顺序、封面、表格和工具，按 [已确认的阅读样式](references/reading-layout.md) 实现；不自动套用重写流程。用户同时要求内容优化时，再做相应研究与编辑。

## 工作流程

### 1. 理解产品与已有内容

读取目标仓库存在的 AGENTS.md、当前内容入口与相关文章，保留他人修改。核验官网/产品资料中的实际能力与可用入口。已有 Brand Context 可以复用，但价格、功能、平台和数据能力重新检查，不要求用户为写文章先建立另一套系统。

读者以可能需要发现、研究、筛选或联系达人的品牌、代理机构及相关团队为主，兼顾学习与研究需求，不默认都是 DTC，也不把无关个人涨粉词强行改成品牌选人文章。

### 2. 先规划，再写作

阅读 [关键词与批量策划](references/planning.md)，对全部输入建立映射：

`原始词 → 相关性 → 搜索需求 → 主题组 → 已有覆盖 → 目标页面 → 处理动作`

批量输入数不等于新增文章数。每个输入词都必须有去向和理由；不能静默漏词，也不能为凑数量改写同一篇。用户明确要求每词一篇或固定篇数时，标出冲突并提出具体替代，不能自行声称已完成该数量。

交付选题表后，在授权范围内直接继续研究、写作，无需逐篇等待确认。只有用户要求先审计划，或实质范围/授权存在冲突时，才暂停相关部分。

### 3. 按页面类型研究与撰写

阅读 [内容与证据及详细写作规格](references/writing.md)，包括篇幅、开头、正文结构、来源、内链、双语与元数据要求。先读取实际搜索结果及支持重要主张的一方资料，再写正文；不能只读本入口就跳过写作规格。

名单就交付真实研究对象，教程就交付能执行的步骤，比较就交付有依据的差异。工具需求不能用纯文章冒充可用工具；需要新交互实现时列明范围，完成已授权部分。

一次可以接收 40 个词；内部按主题与页面类型分组，逐组研究、保存成果、检查，再继续下一组，不在一次连续生成中套同一个模板写完全部。

### 4. 自然连接 QuickKOL

在读者需要执行下一步的位置，说明 QuickKOL 中已核实的能力能帮助完成哪一步。优先使用真实截图、搜索示例或输入输出演示；示例数据明确标注假设。

CTA 与当前任务对应，不每段插产品，也不以产品推广替代答案。不得承诺未验证的实时数据、任意账号覆盖、私人联系方式、自动化发送或效果保证。

### 5. 完成单篇与整批验收

选择正文呈现方式时先读 [表格与图解](references/tables-and-diagrams.md)。比较关系优先用可选中、可本地化的原生表格；有真实先后依赖的操作使用流程图。大段文字不包装成图片，不把并列选项画成先后流程。


- 单篇：标题兑现承诺；答案明确；重要事实有相邻证据；名单/表格/工具确实可用；各语言事实、案例和限制一致。人物示例提供具体作品与观察，不以反复的合作免责声明充当研究深度。
- 配图：按 [配图语言交付与检查](references/figure-localization.md) 建资源清单，检查图片内部的可见文字，不只检查 alt 和图注。英文页不得默认使用中文为主的中英混排图；SVG 执行配套脚本预检，栅格图片与最终页面必须实际看图验收。
- 整批：页面意图和 slug 不重复；没有仅替换城市/行业的空壳稿；检查重复段落、开头、案例和通用结尾。共同来源可复用，但逐篇检查是否支持各自主张。
- 对原始词逐项核对，记录关联页面及完成状态；区分主目标词与同页覆盖的相关词。
- 新稿保留旧页面和 URL；更新旧文须属于本次任务范围。规划中的合组不等于授权合并、删除或重定向已有页面。
- 每个问题记录到具体文章、段落或文件。证据缺口影响核心答案时保留研究状态，不伪称可发布。

### 6. 接入与交接

需要资源制作或网站接入时，阅读 [资源、接入与验证](references/delivery.md)，文章呈现默认沿用 [白底阅读样式](references/reading-layout.md)。只交稿时无需运行整站构建；写作 skill 的说明不会自动改变站点渲染器。

输出建议放在目标工作区的 `outputs/blog/<batch-id>/`：

| 产物 | 内容 |
|---|---|
| 选题映射表 | 每个输入词的主题组、页面、动作、理由和状态 |
| 研究记录 | 查询市场/语言/日期、实际读取的页面、重要主张与来源、缺口 |
| 稿件及资源 | 请求语言的 Markdown、元数据、图注；范围内的网站模块与最终资源 |
| 配图资源清单 | 页面语言、实际资源路径、图内文字模式、alt 与图注；映射到页面后检查实际加载路径 |
| 验收与交接 | 单篇/整批问题及修复、已做检查、未完成项、准确交付状态 |

同一批无需用多份表重复维护相同字段。用清单保存进度，后续继续时从未完成项恢复。

交给另一位执行者时提供整个 `quickkol-blog/` 文件夹，不能只给本入口。安装与启动方式见 [执行说明](README.md)；参考文件、CSS、资源清单模板和预检脚本均随技能交付，不依赖此前聊天、旧手册或本机 localhost 服务。

## SEO/GEO 使用边界

采用直接答案、可独立理解的段落、事实来源、相关内链和可读取页面。不要把固定字数、段落长度、FAQ 数量、统计行数、年份标题或内部 citability 分数当成排名/AI 引用门槛；不编造“我们的研究”来提高评分。

实质性指南沿用 1,500–2,000 英文正文词的默认编辑目标，详见写作规格；这是交付深度参考，不是搜索排名门槛。定义页、名单、比较和工具页按任务调整，不为凑长度填充，也不把“篇幅灵活”当作缩减研究和内容深度的理由。用户当前要求优先。

GEO 复盘区分品牌提及、真实链接引用、产品推荐和来源流量。只有用户要求时执行额外模型查询或监测；记录联网状态、引擎/模型、查询、日期和原始答案，API 回答不等同于消费者产品中的展示。

## 本版依据

参考旧 QuickKOL 编辑交接手册的产品事实边界、双语、来源和交付经验，以及 gr-blog-post / gr-geo-cite 的写作与引用检查思路；本技能可独立执行，不依赖安装这两个技能。按本次讨论重做选词和批量流程，不将旧项目规范整体继承为硬门槛。用户当前任务要求优先；仓库实际实现优先于历史文件路径。

SEO 原则核对于 2026-11-22：[Google 内容指南](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[AI 搜索文档](https://developers.google.com/search/docs/appearance/ai-features)、[canonical 指南](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)。这些文档不支持固定字数或特殊 AI 标记保证引用；规则变化时核验原文。
