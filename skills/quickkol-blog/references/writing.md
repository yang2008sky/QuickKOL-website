# 内容、证据与可引用表达

## 篇幅与交付深度

- 实质性教程、方法和策略指南默认以 **1,500–2,000 英文正文词**规划。统计 `answer` 与 `sections` 英文正文，不用标题、表格、来源或 CTA 凑词数。
- 中文等效完整，可按约 **3,000–5,000 汉字**做初始规划，但不机械换算；保留同等结论、步骤、事实、示例和适用限制。
- 名单、比较、简短定义与工具页按用户需求及页面形式决定长度。策划表说明篇幅安排；如不采用上述指南目标，记录与任务有关的原因，不默默缩水，也不为达标重复内容。
- 深度不足时补具体输入、选择理由、执行示例、错误处理或判断依据，而不是增加行业背景、空泛 FAQ 和通用结尾。

## 文章应该写成什么样

语气专业、实用、正式且易读，像能帮助品牌或机构完成任务的指南。专业性体现在具体解释、证据和有用判断，避免每段都是风险提示，也不把假设包装为标准结论。

既有文章只做展示调整时，不执行下述结构重排、改标题或压缩内容。保留原有写作与信息组织，仅应用 reading-layout.md 的视觉规范；不能把一次简化重写的测试稿替代所有旧文的风格。新写或明确重写文章时再按下述任务框架组织。

通用结构按下面检查，但不强迫所有文章使用相同小标题：

1. **标题/H1**：明确核心问题和真实交付，一页一个 H1；不夸大排名、名单范围或效果。
2. **摘要**：一两句说明帮谁完成什么，不复述标题。
3. **直接答案**：一小段先给定义、结论或操作路径，再交代重要条件；不先铺长背景。
4. **主体**：实质性指南通常可由 5–9 个 H2 组织，按任务调整。每节提供具体信息，不只是“了解受众、制定策略、持续优化”。
5. **方法或选择依据**：说清需要哪些输入、怎么操作、如何判断结果，以及下一步。
6. **证据与执行示例**：事实有相邻引用；示例包括实际操作、查询、筛选记录或清楚标注的假设算例。展示结果，不只给建议。
7. **表格、模板或图**：帮助比较、复用或理解才使用。下载交付真实文件，计算器按交付参考验证。
8. **失败情形与必要问答**：说明实际可能遇到的障碍、替代路径和未知状态；不凑固定 FAQ 数量。
9. **下一步与产品衔接**：告诉读者现在可以做什么，在任务相关处连接 QuickKOL，避免统一营销结尾。
10. **来源、研究日期及限制**：保留可追溯记录；文章末来源列表不替代正文引用。

不同类型另有不同的主体要求：

| 类型 | 正文具体要求 |
|---|---|
| 达人名单 | 开头交代筛选范围与日期；前部给对象概览；每个对象提供官方账号/作品、相关内容、为什么入选及需确认的信息。尽可能链接实际读取的代表作品并说明具体观察，不能仅凭官网首页/简介把通用合作建议扩成一段人物介绍。不能把纯筛选方法包装成名单 |
| 操作教程 | 先说明输入与预期结果；步骤包含具体操作和示例输出；结尾有可执行的核对项。产品步骤须经核验 |
| 产品比较 | 说明比较任务与资料核验日；先给关键差异表；逐项写适用人群、能力、限制、费用口径和来源，允许竞品在某些场景更合适 |
| 定义/方法 | 直接定义后解释范围和区别，给例子与反例，最后说明怎样应用。不用长文掩盖简单答案 |
| 数据/案例 | 交代原始材料、方法、时间范围、结果与有限结论；编辑分析和原始披露分开，不将相关性写为因果 |
| 工具页 | 可用工具或明确入口优先，随后解释输入、输出、公式/方法、使用示例与错误边界；不能让长导言挡住任务 |

## 证据先于正文

每个重要事实保留：主张、原始来源 URL、实际读取日期、资料发布日期/统计期、适用对象与范围、文章位置。相同证据可以复用来源记录，但应用到另一任务时重新检查推论是否成立。

优先一方产品文档、平台官网、具名创作者官方渠道和方法透明的研究。第三方榜单用来找线索，不直接当身份、价格或效果的最终证据。数据、人物地点、粉丝数、商业入口、价格、产品能力和政策等易变事实当次核验。

实质性研究文章默认每种语言至少使用 **2 个不同且有实质支持作用的一方或权威来源，通常按 3 个或更多规划**，并在相关正文段落实际引用。同一报告的转载或同一 URL 多次出现不算独立来源。短定义或纯自有产品操作说明等确实不适用时记录原因，不为凑数硬加无关材料。

来源数量不能代替主张完整性：更多重要事实需要更多相应证据，不能用两条引用概括支撑整篇。正式比较与复杂论断需要多方材料，单一产品自述不能充当独立测试。

区分：来源披露事实、实际团队观察、编辑分析、假设示例、未知。公司自述注明归属，外部研究不改名为 QuickKOL 研究。没有真实测试不得写“我们测试了”“经验证提升”。

数字交代单位、时间窗口、对象、地区、样本与必要分母。粉丝数不等于受众人数，创作者地点不等于受众地点，平台整体改善不等于单次合作收益。未知、不可访问、未核验与零分开。

有合适原始证据时，优先加入 1–2 项影响本篇判断的量化事实，并解释其意义。没有相关数字就用官方定义、操作或可复核方法支撑，不强塞行业规模或把假设算例写成研究。

有用的来源暂不可访问时找替代原始资料；仍无法支持核心承诺就暂缓该稿或缩小范围。联网不可用时可以交计划和明确待核验的草稿，不能声称完成当次事实核验。

## 文章结构按任务决定

- 标题准确承诺页面实际交付，不保留正文不能兑现的名单、工具、年份或排名措辞。
- 第一屏先给直接答案和用途，条件与边界紧跟在相关主张后；不要用长篇免责声明推迟答案，也不删去实质限制。
- 小标题自然描述读者问题。关键定义、方法或结论单独截取仍能读懂，避免依赖模糊代词和前文。
- 方法说明输入、操作与判断；提供真实或明确标为假设的执行示例。比较使用一致字段，重要差异写出适用条件。
- 证据放在相应事实附近。表格、FAQ、流程图有帮助才用，不每篇强制齐全。
- 篇幅服务问题，不复用固定章节、134–167 词段落、“当前日期＋个人经历”开场或通用结尾。
- 专业、清楚、具体。没有作者真实经历时，不照搬 Iris 的个人叙述；不要虚构资质、采访或客户。

每篇应有可说明的独有价值：真实名单、产品操作示例、整理后的比较维度、可复制模板、原创分析或可复核方法。堆来源和复述竞品本身不构成独有价值；也不要求每篇都有原创数据。

人物/名单类文章让读者尽早看到对象、内容方向、代表作品与选择理由；概览表优先放在相关人物详解之前，不默认沉到文末。个人、咨询业务和媒体平台明确区分，标题承诺个人达人名单时不能靠混入机构凑数量。

必要的可用性、授权、数据边界集中说明，在影响某个具体判断时再补充。逐段自查：删掉“不能证明效果/不保证接单/需要核验”等句子后，这节是否仍有足够的对象事实、具体作品分析或可执行信息？如果没有，应继续研究或缩短，不为达到篇幅反复叙述限制。

## 内链与下一步

在读者需要进一步解释或执行时链接站内相关内容、工具或已核实的产品入口。以相关性和阅读路径决定数量，不统一指首页，不机械重复精确关键词锚文本。

实质性文章默认每种语言至少 **2 条有用的正文情境内链**，相关时增加；导航、页脚和统一 CTA 不算。链接分布到需要下一步的段落。若站内确无适合内容，记录缺口，不编造目标或添加无关链接。

验证页面存在、语言正确、fragment 有效；同批稿互链须随同交付并实际接入。旧文回链仅在修改范围内执行。GEO 想覆盖的问题可以成为有用的小节/FAQ，不把一串关键词变体作为问答填充。

## 双语

默认中文与英文等效完整，不把中文缩成英文摘要。两版名单、结论、数字、算例、来源和限制保持一致，语言自然，不机械逐字翻译。针对不同市场新增主张时补充该市场证据，不从另一语言的事实自行外推。

本地化表头、图注、alt、工具标签、错误信息和 CTA。现有网站文本 pair 顺序为 `[中文, English]`，以实际代码为准。

图片内的标题、标签、图例、坐标轴与注释同样属于读者可见内容。alt/图注翻译不代表图中文字完成本地化。自制含文字图默认分别输出目标语言版本；仅无文字图或确有编辑需要且清楚说明的原始截图可跨语言共用。资源选择和验收见 delivery.md。

## 元数据与发布文本

- 标题、H1、摘要和 description 分别承担定位、页面说明与搜索摘要功能，不全部复制同一句。
- 英文标题约 50–65 字符、description 约 140–160 字符作为初稿可读性参考，不为长度删掉关键限定，不当作搜索引擎硬限制。
- 主关键词或自然变体进入标题/直接答案，正文按问题展开，不设密度或强制每个小标题重复关键词。
- slug 简洁、小写、短横线、唯一且稳定。文章的首发、实质更新与研究核验日期分别记录，不用修改日期制造新鲜感。
- 全球读者不能默认适用美国规则；地区性事实或政策注明地区、版本与日期。

## GEO 不制造额外承诺

读者友好的直接答案、自包含段落、清楚事实与真实引用有价值，但不能保证被 AI 引用。内部评分只作编辑线索，不以分数当排名或引用率。

`llms.txt` 不等同 robots.txt，也不保证收录；FAQ Schema 不是 AI 引用必需条件。保留可见内容与结构化数据一致，不为拼数量制造问答。

若执行引用检查：保存固定问题与实际原始回答，分别记录品牌提及、链接引用的具体 URL、推荐语境、联网状态、引擎/模型、日期、错误或跳过。不能仅因域名字符串出现就判定被引用；不把一次观察做成认证或背书徽章。
