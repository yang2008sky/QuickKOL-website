# 资源、网站接入与验证

仅在请求包含相应交付时执行。本节路径是 2026-11-22 本地仓库观察，未来先核验，不覆盖新结构。可在其他工作副本使用，不依赖原作者的绝对路径。

## 阅读呈现

2026-11-23 用户确认：保留原版文章内容与结构，采用已测试的字体、文字颜色、层级字号和间距，文章阅读区使用纯白背景。具体参数、紧凑目录和适用范围见 [reading-layout.md](reading-layout.md)，配套 [blog-reading.css](../assets/blog-reading.css) 可作为现有站点的增量样式。

不因应用阅读样式而改写正文、重命名标题、前置表格或重新设计页面。样式变化与内容变化分别验收；用户只要求本地样张时，不修改线上站点或默认推送全站 CSS。

## 正文表格与图解

执行 [表格与图解规范](tables-and-diagrams.md)。原生表格使用caption、列标题与行标题，手机支持局部滚动和键盘操作。流程有真实顺序时用有序步骤，平级选择用比较表。新增kind必须有渲染分支并兼容既有单文件figure。

## 封面与组件

沿用目标站点实际编辑视觉和尺寸，先检查相邻卡片与当前资源。当前无新要求时，封面按约 16:9、1672×941、sRGB JPEG 交付，quality 通常 80–88。此为站点资源默认值，不是 SEO 规则或正式品牌规范；站点实际要求变化时以新要求为准。

延续明亮、当代、有真实工作逻辑的混合编辑视觉；可交错使用工作现场、单人创作者、环境/物件、编辑拼贴/数据图形、文字/背景五类。奶油白和黑色基底、钴蓝/珊瑚红及少量 #ff484a 可参考当前站点，不让所有图片成为相同场景和配色的复制品。精确文字和数据优先确定性图形；照片与插画按可用图像生成工具制作。

封面与主题对应，批次变化人物、物件、场景、视角或图形形式，避免全部是同一会议桌。真实产品演示使用真实界面；AI 编辑插图不冒充真实达人、客户、测试或活动。按需要披露 AI 来源，alt 描述实际画面。

看过生成图后再验收，检查卡片与详情裁切。保留源图、生成 prompt 或可编辑 SVG；网页最终引用的文件进入项目资源目录，不只留在工具缓存。

### 图内语言与资源选择

有配图时必读 [配图语言交付与检查](figure-localization.md)，使用随附清单与预检脚本，并完成实际页面视觉验收。图内语言、alt/图注语言和按 locale 选择资源是三个分别检查的项目。脚本通过不代替页面语言选择和看图验收。

内容组件以任务价值选择，不强制每文加计算器。下载链接必须有真实文件；新 tool.kind 要有真实渲染/计算分支。计算器说明公式、单位、输入边界和默认假设；区分空值与零、零分母与有效零结果，对数学逻辑做正常/无效/边界测试并实际操作。

## 当前 QuickKOL 接入要点

先读 package.json、现有单篇模块及以下路径的实际代码：

| 路径 | 当前职责 |
|---|---|
| src/blog-registry.js | 汇总内容模块，客户端和静态构建共同读取 |
| src/blog.js | 详情/列表、内链与引用、交互和阅读时间 |
| scripts/build-blog-pages.js | 真实静态 HTML、分页与构建输出 |
| src/semrush-editorial.js | 历史 helper 与内置来源，注意默认日期和字段转换 |
| src/localized-paths.js、src/blog-localization-manifest.js | 语言路由与额外语言覆盖 |
| public/assets/blog/、public/downloads/ | 网页资源与真实下载 |

文章不是 Markdown CMS。只交 `.md` 不代表已经接入网站。新增模块按当前 registry 方式注册，检查客户端和生产静态页都收到新文，不能照旧手册在两个入口各重复注册。

保留旧文章、slug 和资源；新稿使用唯一 slug，按当前列表约定进入集合。更新旧文须明确在任务范围，不用新增请求静默覆盖旧文。

目前文本为 `[中文, English]`，sections 包含标题 pair、正文 pair 与来源 ID；最终 source 对象有 id、terms、label、url。阅读 helper 输入与最终文章对象的区别：历史 `article()` 的 sources 可能按内置 evidence key 解析，不能任意传来源对象假设有效。

现有内链与 citation 依赖正文术语匹配。只填 internalLinks / sources 不等于正文已经有链接；术语需在相应语言的段落实际出现。Markdown 链接也不保证被渲染器解析。构建后看 HTML 的真实锚文本、href、来源归属和 fragment。

日期显式填写，首发日、实质更新日与资料核验日分开；不继承 helper 历史默认日期。沿用当前真实署名与自动阅读时间机制，不虚构作者资质或手填分钟数。

当前英语 `/blog/<slug>/`、中文 `/zh/blog/<slug>/`，以实际路由核对；不擅自改成 `/en/blog/`。其他语言已有覆盖机制，但不因存在 manifest 就自动为新文声明全语言上线。只为实际交付、可访问的语言提供 alternate，翻译页通常自指 canonical 并互指 hreflang。

## 验证分层

1. **只交稿**：检查意图兑现、证据、双语一致性、词到页面映射、单篇与批次重复。链接能访问不代表事实支持主张。
2. **已接入网站**：按当前 package.json 构建。已安装且未变化的依赖不重复安装；实际需要时才安装。当前命令为 `npm run build`，相关现有测试可用 `node --test tests/*.test.js`，并运行 `git diff --check`（仓库内）。不声称存在未定义的 SEO 测试命令。
3. **生产产物**：检查新增文章真实 HTML、title/H1、description、正文引用、canonical、hreflang、OG、结构化数据、sitemap 和资源；不能把 SPA fallback 的 HTTP 200 当成页面存在。
4. **视觉/交互**：分别检查所交付语言的桌面及手机文章卡片、详情、标题层级与换行、紧凑目录及锚点、白底与文字颜色、表格、图片实际懒加载与图内语言匹配、CTA 与下载。新增交互实际改输入并核对结果。只调样式时额外比对正文、标题、表格与顺序未变。浏览器不可用就明确视觉待验收，继续其他检查。

旧批次审计脚本通常绑定固定列表，先确认检查覆盖本次文章；构建成功不代替内容验收。报告执行过的检查及其范围，不能笼统说“全站通过”。
