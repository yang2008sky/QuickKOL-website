# 正文表格与图解

2026年11月24日确认的 QuickKOL 阅读规范。以任务决定形式，保持正文、来源与元数据对应。

## 选择形式

| 信息关系 | 优先形式 | 核对重点 |
|---|---|---|
| 对象、任务、产品或条件的比较 | 原生 HTML 表格 | 相同字段、可追溯、可选中文字 |
| 字段含义、输入输出、对应关系 | 两至三列表格 | 表头清楚，范围一致 |
| 有真实先后顺序和依赖的操作 | 流程图或有序步骤组件 | 顺序、连接和终态正确 |
| 三种平级方案或叙事形式 | 比较表或无序选项 | 不画成必须顺序执行的流程 |
| 有量化依据的变化或分布 | 数据图 | 单位、时间、分母、来源及假设标识 |
| 纯说明、提示与条目 | 普通正文或列表 | 不将文字截图或导出成图片 |

不得为视觉丰富编造评分、百分比、坐标或排名。人物与平台可作资料研究对象，表格不能暗示已确认的合作能力或背书。

## 已确认的表格样式

- 桌面正文14px、手机13px，行高1.6左右，标题18–20px。数字是编辑默认值，可根据实际文字调整。
- 两至三列优先，列宽按内容分配。比较对象名称适度加粗，避免整行粗体。
- 白色底、浅灰蓝表头、细分隔线、约12px圆角；每格内边距约16–20px。
- 仅用少量蓝、珊瑚和绿色细标记区分类别，不用大色块或巨大字体。
- caption表达本表用途；thead/th scope=col，必要时首列th scope=row。
- 手机保持可读字号，宽表仅在自身容器内横向滚动。容器可聚焦，有本地化的左右滑动提示，键盘也能滚动。不要让整页横向溢出。
- 图注说明编辑示例、假设、来源范围等必要条件，不重复整张表。

## 流程组件

桌面可横向排列，手机改为竖向。以小型步骤编号、短标签和连接线表达真实顺序，字号约14px/13px。使用ol/li等语义结构，避免每步做成巨大的文字卡片。不同收入类别或三种创意格式是平级选项，不能因为有三项就加箭头。

## 数据与渲染

沿用仓库既有接口。当前项目figure可采用kind=comparison-table，包含title pair、headers pair数组、rows单元格pair数组；kind=process-flow包含title pair和steps pair数组；共同保留afterSection与caption pair。英文/中文pair仍为[中文, English]。使用前检查当前渲染器，不能只添加字段而没有实现。

兼容旧figure.file，含文字图的files映射按locale选择。只调整指定文章的组件和样式，不据此批量改变其他历史文章。图片资源清单应只包含页面实际加载的图片，不把原生表格列成图片。

## 验收

检查中英文桌面与约390px手机页面。实际查看字号、换行、比较列、caption、空值和长名字；测试表格内部滚动及键盘焦点。确认目录目标存在、原文与来源未丢失；新增渲染kind覆盖静态构建和客户端入口。截图与自动化DOM检查分别记录，脚本成功不代表视觉已审阅。

配套 [blog-components.css](../assets/blog-components.css) 包含已确认的比较表与流程样式。先检查实际类名和范围，放在站点原有样式之后；仅启用当前任务已授权的文章。
